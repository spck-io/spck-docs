# <a name="git-support"></a>Поддержка Git

Spck поддерживает Git для локальных проектов на Android и iOS, в браузере и для удалённых проектов через Spck CLI. Руководство описывает учётные данные провайдеров, pull request, просмотр коммитов, разрешение конфликтов и ограничения платформ.

Базовая интеграция Git, история коммитов и разрешение конфликтов доступны в бесплатной версии. [Расширенная интеграция Git](#enhanced-git-integration) добавляет управление pull request и просмотр различий файлов коммита.

## <a name="git-credentials"></a>Учётные данные Git и pull request

Откройте **Git menu → Git Credentials**, выберите провайдера и сохраните токен доступа. Ссылки настройки и справки ниже открываются в новой вкладке, чтобы можно было вернуться в Spck и вставить токен.

| Провайдер | Настройка токена | Разрешения для Git и pull request |
| --- | --- | --- |
| GitHub | <a href="https://github.com/settings/personal-access-tokens/new?contents=write&amp;pull_requests=write&amp;metadata=read&amp;name=Spck-Editor&amp;expires_in=90" target="_blank" rel="noopener noreferrer">Создать токен GitHub</a> · <a href="https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens" target="_blank" rel="noopener noreferrer">Руководство по настройке</a> | Выберите репозиторий. Ссылка заранее выбирает **Contents: Read and write**, **Pull requests: Read and write** и **Metadata: Read**. |
| GitLab | <a href="https://gitlab.com/-/user_settings/personal_access_tokens?name=Spck-Editor&amp;scopes=api" target="_blank" rel="noopener noreferrer">Создать токен GitLab</a> · <a href="https://docs.gitlab.com/user/profile/personal_access_tokens/#prefill-personal-access-token-details" target="_blank" rel="noopener noreferrer">Руководство по настройке</a> | Ссылка заранее выбирает область `api` для merge request. |
| Bitbucket Cloud | <a href="https://id.atlassian.com/manage-profile/security/api-tokens" target="_blank" rel="noopener noreferrer">Создать API-токен</a> · <a href="https://support.atlassian.com/bitbucket-cloud/docs/create-an-api-token/" target="_blank" rel="noopener noreferrer">Руководство по настройке</a> | Выберите **Create API token with scopes**, затем **Bitbucket** и вручную отметьте `read:repository:bitbucket`, `write:repository:bitbucket`, `read:pullrequest:bitbucket`, `write:pullrequest:bitbucket`. Для API используется email аккаунта Atlassian. |
| Azure DevOps | <a href="https://learn.microsoft.com/en-us/azure/devops/organizations/accounts/use-personal-access-tokens-to-authenticate" target="_blank" rel="noopener noreferrer">Руководство по PAT</a> | Откройте **User settings → Personal access tokens → New Token** в организации, выберите организацию и вручную **Code (Read & write)**. |

Для создания pull request закоммитьте и отправьте исходную ветку, затем откройте **Git menu → Create PR**. Выберите удалённый репозиторий, учётные данные, другую целевую ветку, заголовок и описание. **Generate with AI** может подготовить текст по закоммиченным изменениям от общего предка веток; сначала выполните fetch целевой ветки. Проверьте черновик перед **Create PR**. В GitLab создаётся merge request.

Создание и управление pull request — **функция Premium** в составе [расширенной интеграции Git](#enhanced-git-integration). В Lite она входит в разовую покупку приложения. В полной версии войдите с активной подпиской Supporter, Gold или Node либо под аккаунтом с пожизненной разблокировкой терминала Spck for NodeJS.

## <a name="pull-request-management"></a>Управление pull request (Premium)

Управляйте запросами, не покидая редактор. Поддерживаются **GitHub.com, GitLab.com, Bitbucket Cloud и Azure DevOps**; в GitLab запросы называются merge request.

1. Откройте Git-проект и добавьте токен провайдера в **Git menu → Git Credentials** с указанными выше разрешениями.
2. Откройте **Branches menu → Pull Requests** и выберите репозиторий и учётные данные для списка открытых запросов.
3. Выберите запрос, чтобы увидеть заголовок, описание, автора, исходную и целевую ветки и статус.
4. Выберите изменённый файл и изучите различия только для чтения перед слиянием.
5. Используйте **Merge** для допустимого слияния или **Close** для закрытия без слияния. Требования ревью, проверок, прав токена и правил веток сохраняются; черновики и запросы с конфликтами нельзя слить из этого диалога.

Нажмите **Refresh**, чтобы обновить список после изменений у провайдера. В деталях запроса также есть ссылка на провайдера для ревью, проверок и других действий.

Новый запрос создаётся через **Git menu → Create PR**, как описано выше. Если исходную ветку ещё нужно отправить, диалог предлагает **Push** перед созданием. Необязательная подготовка текста с ИИ использует настроенный сервис и его лимиты; она отделена от доступа к pull request в Lite.

При ошибке из-за разрешений создайте или обновите токен по ссылке провайдера, сохраните его в **Git Credentials** и повторите попытку. Черновик PR сохранится.

## <a name="enhanced-git-integration"></a>Расширенная интеграция Git

Расширенная интеграция Git добавляет два инструмента проверки и публикации изменений:

- **Управление pull request:** создание запросов, просмотр открытых запросов, файлов и различий, слияние и закрытие. Настройка и действия описаны в разделе [управления pull request](#pull-request-management).
- **Просмотр коммитов:** изучение изменённых файлов и различий без изменения рабочих файлов.

Откройте **History** на панели Git и выберите коммит для просмотра добавленных, изменённых и удалённых файлов. Выберите файл для просмотра различий с первым родителем только для чтения. Первый коммит сравнивается с пустым деревом. Используются закоммиченные версии; незакоммиченные правки не влияют на различия. Двоичные файлы нельзя показать как текстовые различия.

Также можно удерживать запись истории, или щёлкнуть правой кнопкой мыши, и выбрать **View Commit**.

Расширенная интеграция Git включена в:

- **Spck Editor Lite:** постоянная разблокировка разовой покупкой, без входа в аккаунт.
- **Пожизненная покупка терминала Spck for NodeJS:** постоянная разблокировка для аккаунта владельца; требуется вход.
- **Подписки Supporter, Gold или Node:** доступ на время активной подписки; требуется вход.

Базовая интеграция Git и история коммитов остаются доступны бесплатно. Подробности планов — на странице [цен](https://spck.io/pricing).

## <a name="merge-conflict-resolution"></a>Разрешение конфликтов слияния

Просмотрщик различий также помогает разрешать конфликты рабочих файлов. Это базовая функция Git, не требующая Premium.

1. Откройте конфликтующий файл из списка изменений Git.
2. Для каждого конфликта выберите **Accept Current**, **Accept Incoming** или **Accept Both**. Можно также объединить изменения вручную в файле.
3. Проверьте результат. Удалив все маркеры конфликтов, нажмите **Resolve** в просмотрщике, чтобы добавить разрешённый файл в индекс.
4. Разрешите остальные файлы и закоммитьте слияние.

На сенсорных устройствах удерживайте файл или запись Git для контекстного меню. Буквенные статусы Git дополняют цвета имён, помогая различать изменения.

## <a name="git-limitations"></a>Ограничения Git

### <a name="git-limitations-overview"></a>Обзор

Реализация Git зависит от расположения проекта и используемой версии Spck:

| Среда | Реализация Git | Основные ограничения |
| --- | --- | --- |
| Приложения Android и iOS, включая Lite и Spck for NodeJS | Нативно скомпилированная **libgit2** для локальных проектов | Проект должен находиться в хранилище устройства; ограничения ресурсов и файловой системы сохраняются. |
| Браузер и встроенный редактор | [isomorphic-git](https://isomorphic-git.org/) на JavaScript | Ограничения памяти, хранилища и сети браузера. |
| Удалённые проекты через Spck CLI | **Исполняемый файл Git** хост-компьютера | Используются ресурсы, файловая система, учётные данные и установленный Git хоста. |

Текущие мобильные сборки используют нативный Git вместо браузерного движка. При сообщении **Native Git requires a device folder** перенесите проект в хранилище устройства. Проекты только в браузерной базе данных редактора не могут использовать мобильный нативный Git-клиент.

Управление pull request напрямую обращается к API провайдера с токеном из **Git Credentials**. Cookies входа браузера не используются, ответы API не кэшируются, чтобы обновление получало актуальные статусы и ветки. Разрешения описаны в разделе [учётных данных Git и pull request](#git-credentials), провайдеры и действия — в [управлении pull request](#pull-request-management).

### <a name="git-limitations-memory"></a>Ограничения памяти

- Нативный Git на Android и iOS выполняет операции вне JavaScript-движка Git. Ограничения памяти браузерного движка не являются фиксированным пределом мобильного Git.
- Нативному Git всё равно нужны свободные память и диск. Большие репозитории или pack-файлы могут превысить ресурсы устройства, вызвать ошибку или завершение приложения системой.
- Браузерный Git ограничен памятью JavaScript и хранилищем браузера. Обработка больших pack-файлов может требовать много памяти и приводить к ошибкам клонирования или fetch.

> 💡 **Совет:** Для больших репозиториев по возможности используйте неглубокое клонирование или работайте с меньшей частью репозитория.

### <a name="git-limitations-symlinks"></a>Совместимость символических ссылок

- Браузерное хранилище и слой файловой системы устройства в редакторе используют **эмулированные символические ссылки** для репозиториев со ссылками.
- Переход мобильного Git на libgit2 не снимает ограничений файловой системы и не гарантирует настоящих ссылок ОС.
- Эмулированные ссылки могут иначе работать с инструментами сборки, пакетными менеджерами и скриптами, ожидающими настоящих ссылок и разрешающими их цели во время выполнения.
- Для настоящих ссылок используйте удалённый проект на хосте с подходящими файловой системой и разрешениями.

### <a name="git-limitations-cli"></a>CLI как альтернатива

Для больших репозиториев или задач, требующих файловой системы и Git-инструментов хоста, используйте **удалённый проект через Spck CLI**. Операции выполняются **исполняемым файлом Git на хосте**, пока вы редактируете файлы в Spck:

- Операции используют память и диск хоста вместо ресурсов мобильного устройства или браузера.
- Символические ссылки зависят от поддержки файловой системы и разрешений ОС хоста.
- Команды, отсутствующие в элементах управления редактора, выполняйте инструментами Git хоста.

Подключение хоста описано в [начале работы со Spck CLI](./cli-start). Удалённым проектам нужен аккаунт Spck, действуют лимиты вашего плана; требования подписки Lite см. в разделе [удалённых проектов](./editor-lite#remote-projects). Клонирование в хранилище устройства по-прежнему использует нативный Git-клиент мобильного приложения.
